# cairn — 设计文档

> 断片了？先读这一份，再读 `PROGRESS.md`。

---

## 一句话

基于 **C++20 + RocksDB**、兼容 **Redis RESP 协议**的**单机 KV 存储引擎**。

用人话说：**写一个进程，它假装自己是 Redis，官方客户端认不出真假，但数据实际存在 RocksDB 里。**

---

## 做完长什么样

```
$ ./cairn --port 6380
[cairn] listening on :6380  engine=rocksdb

$ redis-cli -p 6380              ← 别人写的官方客户端，直连你的进程
127.0.0.1:6380> SET name jixing
OK
127.0.0.1:6380> GET name
"jixing"
127.0.0.1:6380> EXPIRE name 10
(integer) 1
127.0.0.1:6380> TTL name
(integer) 7

$ kill %1 && ./cairn --port 6380   ← 重启
127.0.0.1:6380> GET name
"jixing"                            ← 数据还在（落盘了）

$ redis-benchmark -p 6380 -t set,get -n 100000 -c 50
SET: 82,300 requests per second   p99 = 1.8ms
GET: 95,100 requests per second   p99 = 1.3ms
```

**最后四个数字 = 简历上那条 bullet 的全部来源。**

## 协议是怎么回事（RESP）

客户端和服务端之间就是一串有格式的字节。`redis-cli` 敲 `SET name jixing`，网线上跑的是：

```
*3\r\n$3\r\nSET\r\n$4\r\nname\r\n$6\r\njixing\r\n
```

| 片段 | 含义 |
|---|---|
| `*3\r\n` | 接下来是一个有 3 个元素的数组 |
| `$3\r\nSET\r\n` | 长度为 3 的字符串 `SET` |
| `$4\r\nname\r\n` | 长度为 4 的字符串 `name` |
| `$6\r\njixing\r\n` | 长度为 6 的字符串 `jixing` |

服务器回 `+OK\r\n` 就完事了。常用回复类型：

| 首字节 | 类型 | 例子 |
|---|---|---|
| `+` | 简单字符串 | `+OK\r\n` `+PONG\r\n` |
| `-` | 错误 | `-ERR unknown command\r\n` |
| `:` | 整数 | `:1\r\n` |
| `$` | 长度前缀字符串 | `$6\r\njixing\r\n`，空值是 `$-1\r\n` |
| `*` | 数组 | `*2\r\n...` |

**协议存在的唯一理由：TCP 只保证字节按序到达，不告诉你一条消息从哪到哪。`\r\n` 和 `$6` 这种长度前缀就是用来划边界的。**

（实测抓包，一次性模式下 `redis-cli -p 6380 PING` 发的是 `*1\r\n$4\r\nPING\r\n`；交互模式下一连上先发 `*2\r\n$7\r\nCOMMAND\r\n$4\r\nDOCS\r\n` —— 所以 `COMMAND` 必须应答，否则 redis-cli 握手就卡住。）

## 路线图：七个毛病

**这个项目不是照蓝图施工，是被问题推着走。** 每修一个毛病，长出一个模块。

| # | 毛病 | 长出什么 | 状态 |
|---|---|---|---|
| 0 | 什么都没有 | v0：监听 6380，收到任何字节回 `+PONG\r\n` | ✅ 已完成 |
| 1 | 只服务一个客户端就退出 | 循环 accept + 循环 read + 正确处理返回值 | ⬜ |
| 2 | 客户端敲 `SET` 你还是回 PONG | **RESP 解析器**（含半包/粘包处理） | ⬜ |
| 3 | 解析出来了但没地方放 | **存储层**（第一版 `unordered_map`） | ⬜ |
| 4 | 第二个客户端要排队等第一个 | **epoll 事件循环**（单 Reactor 单线程） | ⬜ |
| 5 | 命令加到第 8 条，if-else 一百行 | **命令分发表** | ⬜ |
| 6 | 重启后数据全没了 | **接 RocksDB**（逼出 `IStore` 抽象） | ⬜ |
| 7 | "你这玩意到底多快？"答不上来 | **压测**：QPS / p99 数字 | ⬜ |
| 8 | 读比写慢，每次读都穿透到 RocksDB | **热点缓存层**（进阶点） | ⬜ |

## Scope 冻结

### 做（Phase 1 命令集）

| 组 | 命令 |
|---|---|
| 连接/元 | `PING` `ECHO` `QUIT` `SELECT`(仅回 OK) `COMMAND`(回空数组) |
| 字符串 | `SET key val [EX s]` `GET` `DEL` `EXISTS` `INCR` `DECR` `INCRBY` |
| 过期 | `EXPIRE` `TTL` `PERSIST` |
| 管理 | `DBSIZE` `FLUSHDB` `INFO`(极简) |

`redis-benchmark -t set,get,incr` 只用到这几条，压测链路是通的。

### 不做清单（防蔓延，写死）

list / hash / set / zset 全部数据类型、`MULTI/EXEC` 事务、Pub/Sub、Lua 脚本、`KEYS`、`SCAN` 游标、阻塞命令（BLPOP 等）、主从复制、集群、AOF/RDB、ACL/AUTH、TLS。

**任何时候想加功能，先来看这张表。不在"做"里的一律推到 Phase 2。**

## 模块切分

```
src/
├── main.cpp            启动、参数、把各层拼起来
├── net/
│   ├── EventLoop.*     事件循环（依赖 Poller 接口，不依赖 epoll）
│   ├── Poller.h        ← 抽象接口，9 月换 io_uring 的缝在这里
│   ├── EpollPoller.*   Phase 1 唯一实现
│   ├── Acceptor.*      监听 + accept
│   ├── Connection.*    单连接的读写缓冲与生命周期
│   └── Buffer.*        应用层读写缓冲区（半包的容身之处）
├── proto/
│   ├── RespParser.*    字节流 → Command，纯逻辑，可单测
│   └── RespWriter.*    Reply → 字节流
├── cmd/
│   ├── CommandTable.*  name → handler 查表
│   └── commands.*      各命令的实现
└── store/
    ├── IStore.h        ← 存储抽象接口
    ├── MemStore.*      unordered_map 版（毛病 3）
    ├── RocksStore.*    RocksDB 版（毛病 6）
    └── CachedStore.*   装饰器，热点缓存（毛病 8）
```

**留缝的位置（重要）**：9 月要换 io_uring，但 epoll 是 Reactor（"可以读了，你自己去读"），io_uring 是 Proactor（"我已经替你读好了"）—— 两者语义不同，**缝不能只留在 `Poller` 这一层**。真正的抽象边界应该是：**"IO 后端负责把完整的字节交给 `Connection`"**，Connection 之上不感知是谁读的。Phase 1 只要保证 `EventLoop` 不直接调 `epoll_*`、`Connection` 不直接调 `read/write`，缝就留住了。

## 关键设计决策（面试必被问，答不出不许合入）

| 决策 | 取舍话术 |
|---|---|
| **单 Reactor 单线程** | 刻意对齐 Redis 本尊模型。瓶颈在内存和网络不在 CPU；单线程免掉锁和竞态，可预测性强。代价是吃不满多核 —— 这是明确的取舍，不是没想到。 |
| **用 RocksDB，不自研 LSM-tree** | 正确的工程分层。RocksDB 负责"怎么把数据可靠放到磁盘"，我负责它之上的一切。自研 LSM 是半年的活，且不会比它更可信。 |
| **不自研 WAL** | RocksDB 自带 WAL。再写一个既重复又没有可比基线，证据链是空的。**否决。** |
| **过期策略不算进阶点** | 支持了 `EXPIRE` 就必须实现惰性 + 定期删除，这是功能正确性，是基本功不是亮点。 |
| **进阶点 = 热点缓存层（待定，毛病 7 之后再定）** | 唯一证据链完整的候选：有命中率曲线、有 zipfian/uniform 对比、有八股联动（淘汰算法、穿透/击穿/雪崩）。 |

### 进阶点必挨的那一刀（提前准备好答案）

> **"RocksDB 自己有 Block Cache，你这层是不是重复造轮子？"**

答不出来整个进阶点崩盘。答得出来，它就从"烂大街的 LRU"变成"你真的懂 LSM 读路径"。
（提示方向：Block Cache 缓存的是什么粒度的东西？命中它之后，还剩多少工作没省掉？）

## 诚实定位

- **对标物**：Apache Kvrocks（原携程）、Pika（360）、Tendis（腾讯）—— 同一赛道的工业实现。
- **cairn 是学习型重实现**，不是竞品。面试时**主动**说出这一点是加分，被问出来是减分。
- **没有实用价值**：Redis 快 10 倍，Kvrocks 完整 100 倍。
- **全部价值在于**：面试官指着任何一层，你都能聊 20 分钟，聊的是自己踩过的坑。
- **简历不吹**："单机版 + 真数字"，不写"高性能分布式"。

## 工作协议（铁规）

1. **代码王吉星亲手写**，Claude 只教、只评审，不代写。
2. **动手前先复述设计**（为什么这样、备选是什么、为什么否决备选）。
   **⚠️ 2026-09-25 修订 —— 复述的【粒度】跟着熟悉程度走：**

   | 情况 | 怎么做 |
   |---|---|
   | 这块东西**见过、做过类似的** | 一次复述**整个模块**的设计，通过了再动手（原规则） |
   | 这块东西**完全没见过** | **分层复述**：复述这一小块 → 写这一小块 → review → 下一块 |

   > **为什么改**（他自己的比喻）：「我现在第一层的基础都没学好，却要想第二三层的设计」。
   > **一次性复述完整设计，默认了他已有全局判断力。这个前提在陌生模块上不成立** ——
   > 等于拿二三层的图纸，考一个还没砌过砖的人。
   > **铁规 1（他写代码）和铁规 3（写完逼问）不变。变的只是「设计」从一次性改成跟着代码走。**

3. **写完 Claude 以面试官身份逼问 review —— 讲不透的不许合入。**
4. **讲透一块，盖住笔记复述一遍，才标 🟢。** 只"听过"记 🟡。
5. **先抛裸问题让他自己想**，他说"要提示"才给。
   **⚠️ 2026-09-20 修订 —— 逼问有适用边界：**
   > **「逼问」只在【零件齐全、只差组装】时有用；零件本身没见过，逼问就是浪费时间。**
   > **判据（他可以直接对 Claude 用）**：「这东西我是**想不起来**，还是**压根没见过**？」
   > 答案是"没见过" → 直接说 **「这个我没见过，讲」**。那不是认输，是纠正 Claude 用错了工具。
6. 事实层诚实，结论层不自贬。**答错了直接说错，别打圆场。**
7. **一次只推进一个主题。** 给目标 + 验收标准。
8. 他说"**蒙了 / 停一下 / 我们停下来整理一下**" → 立刻停止输出新内容，先对齐状态。
9. **长回答结尾用「PS：」标出唯一要内化的一条。**
   过滤器：**"这次之后，我下次动手会有哪一步不一样？"**
10. shell 命令用 `rtk` 前缀（`git` 命令建议裸跑，原生输出的提示更有教学价值）。
11. **Claude 不主动 commit** —— 改完文件就停，报告改了什么，等他自己提交。
